# 网络参考

## 路径

默认 Direct-first 优先验证 LAN、IPv6 或 IPv4 UDP 直连；Relay 同时准备但只在有界直连窗口到期或已建立 Direct 明确失活后兜底。Direct 的确认必须来自当前网络 generation、peer session、候选 epoch 和加密业务路径；控制面可达或探测 ACK 不能单独证明业务互通。

## 服务端端口

| 组件 | 默认内部端口 | 公网边界 |
| --- | ---: | --- |
| Control | 18080 | 通过可信 HTTPS 反代公开 |
| Relay TLS | 18081 | 按需公开 |
| Relay metrics/readyz | 18082 | loopback only |
| UDP observer | 由配置指定 | 可选，不是 Relay 数据端口 |

Control 反向代理必须支持 WebSocket Upgrade。Relay TLS 不能用 Control 的普通 HTTP 代理规则代替；证书、audience、region、ticket keyring 和撤权 feed 必须同时匹配。

## MTU 与 DPLPMTUD

Relay 路径使用保守的业务报文预算。DPLPMTUD 从安全下限开始，成功后逐步提升，失败或取消时回退；Direct 与 Relay 的预算、网络 generation 和连接 epoch 不能混用。高于 1380 的 Relay 路径应提示 PMTU blackhole 风险。

诊断至少显示当前路径、selected MTU、探测状态、失败 reason code 和建议值。MTU smoke、真实 TUN、NAT、网络切换和业务流量是不同验证层，不能互相冒充。

## NAT 限制

STUN 观察到公网映射不代表对端可以入站。目的地址相关的 mapping 与入站 filtering 分开记录：没有独立入站证据时，filtering 为 `Unknown`。只有收到该 socket 此前未联系过的另一个 IP 的合法 CHANGE-REQUEST 响应，才可确认 endpoint-independent filtering；超时或同 IP 换端口响应不足以判定严格过滤。家庭宽带、校园网、企业网、移动热点、CGNAT 和双受限 NAT 的结果不同；Direct 失败时应回退 Relay 或明确提示环境限制。

普通 NAT profile 的 `observations` 只包含其 `local_addr` 对应主 socket 的 STUN 序列，不能把 socket pool 中并行分配的端口接在后面推断随机性或步长。主 socket 无响应而 pool 成员有公网映射时，pool 候选仍可证明存在可用的 pool-backed Direct 尝试入口；这不会把不同 socket 的样本伪装成同一分配序列，也不会从单次 pool 映射授予预测能力。

## 网络切换与恢复

UDP 路由监测沿用选择绑定接口时的同一份路由签名，不在 STUN 初始化后重新建立基准。连续两次一致的非空变化触发 socket 重建；Android 的有效网络回调可直接触发重建。回调只跳过本次等待，之后绑定失败仍使用非零、有上限的指数退避。路由签名依据接口与网关，不能单独识别这两者均未变化的网络切换。

Android 允许此前仍在线的默认网络再次成为默认网络。只有真实 `onAvailable` 可以重新选择网络；属性变化不能复活其他 handle。回调保留至多一个等待属性的网络公告，并继续核对 service/bridge incarnation；旧 handle 的属性和丢失通知不能撤销当前网络。

网关映射缓存同时绑定网络 generation、UDP 实例、发布 owner、绑定地址、LAN 地址和网关。身份变化清除旧成功租约与失败退避；迟到的发现结果不能覆盖替代网络的缓存。后台合并候选在 100 ms 有界本地提交中复核网络和发布身份，不刷新保留的 STUN 采样年龄，也不把临时 host 快照提升为完成测量。

Control 注册退避和认证冷却期间仍处理网络变化通知，通知 HTTP 连接池重建并使旧时钟样本失效。临时注册失败可提前重试；永久认证失败保留原 60 秒冷却截止，不被普通命令或重复网络通知提前结束或重新计时。恢复等待前撤销旧注册授权，只有成功重新注册后才能恢复关键发送通道。

## 探测成本与候选覆盖

前台 UDP 探测复用进程内全局预算，同时限制网络、peer、peer/目标 IP 和跨 peer 的目标 IP 聚合。目标 IP 聚合上限为每秒 448、每 60 秒 4500；原有进程上限每秒 512、每 60 秒 6000 不变。已确认路径的保活和加密业务不消耗这份前台扫描预算。该限制是单进程的，多房间独立 daemon 之间不宣称已经具备跨进程预算协调。

Relay 退避心跳使用独立的低速预算，并向仍在一秒窗口内的前台突发让行。本地和进程级繁忙查询都会清理到期计数，因此心跳恢复不依赖另一轮前台探测；一分钟持久预算不会随短窗口一同清空。

端口预测使用宽整数后取模，剔除端口 0 和重复候选；当前批次的首选端口不会被历史学习步长替换。NAT 标签保留有符号分配步长，反向分配器的负步长不能使整条 profile 的 generation、观测序号或注册生命周期丢失。历史同方向假设仅占用原有候选预算中的有限份额。学习覆盖率表示近期样本一致性，不是实际打洞成功概率。

非固定 Linear 测量中的跳号可能来自其他流量消耗端口。没有历史步长覆盖、样本和候选均不回绕时，rendezvous 预测可在原候选数量内加入同方向较小步长的有限反序前缀，保留原首选及后续候选。该前缀最多占用原本受保护的前 8 项；不满足边界时保留原窗口。较小步长只是候选假设，不改变模型置信度，也不授予端口域或固定锚证据。混合候选不按固定步长窗口重排。

Hard↔Hard 候选早于对端版本化 NAT profile 到达时，会在原候选任务内请求一次 roster 刷新并有界等待真实元数据；不会从信令声明伪造 generation，也不会延长 rendezvous 截止。只有本端注册已获服务端确认、对端当前注册同时声明 `hh2_pair_nomination` 和 `hh2_plan_v2` 时才协商 `hh2`；缺少任一能力时使用兼容流程。已识别的 `hh2` 报文若无效，不回退为旧协议。

接收候选任务仍为每 peer 一个执行位置和一个等待位置。同身份、同代际下，仍在原有效时间窗内的 Hard↔Hard OFFER/ANSWER 优先于普通候选刷新；同 token 的排队重放保留原报文，普通候选之间继续保留最新值。此优先级不放宽注册、网络和 peer session 围栏，不延长计划截止，也不保证任务已经进入测量或扫描。

新的 Hard↔Hard OFFER 在替换候选 epoch 前，最多等待已有的加密直连验证 owner 250 ms，避免撤销正在返回的验证 ACK。等待包含本地锁获取时间，不因验证 owner 替换而续期；超时后继续正常候选处理，身份变化或取消则停止原任务。握手和首次 ANSWER 不受此等待影响，Direct 仍须由原验证规则确认。

`hh2` 通过专用 socket 的有序测量记录每次实际 STUN 发送及响应，包括已发出但未观测到映射的尾部。分配作用域、端口范围、有符号步长、网络 generation、样本年龄和预测时距共同决定预测是否可用；并发 STUN gather 仅提供置信度受限的策略提示。预测使用生产端口域，不根据模拟器范围推断。发布候选前重新检查测量和 socket 身份，过期证据不继续发布。预测和固定锚的每个新 socket/目标组合在实际首次发包前还必须满足原预测截止；仅成功系统调用才能登记首发，收到 Probe 或 ACK 不能替代。已经发出的原组合重传和确认沿原阶段截止执行。

`hh2` 优先选择最近一次本地 gather 已响应、RTT 较低的配置内 IPv4 STUN 节点；只有三个节点有成功提示时，使用三个主 socket 观测，避免让已超时节点占用交叉测量。提示不足时仍保留配置节点重新测量。历史映射不能替代本轮响应、授予固定锚或确认 Direct。每个请求按剩余请求数分配原 1200 ms 总预算，并受配置的 STUN 超时限制；较慢节点可使用前面快速响应留下的时间，总截止和请求数量不增加。普通 fresh mapping 仍保留单请求 350 ms 上限。

早期未观测发送不授予共享分配器证据。其后若存在至少三条完整、连续、同 socket 的末尾观测，且测量账本中没有尾段之后的发送，可重新建立该 socket 的预测基线；发布时再次核对账本、观测与模型身份。只有未借用完整分配证据、未携带固定锚的独立预测尾段，才按尾段的真实采样起点检查年龄；原批次到计划首发的预测时距仍受原上限约束。末次发送未知、重复测量目标或不一致的顺序不能用较早的成功样本掩盖。这份账本不证明共享 NAT 上的其他业务没有分配端口。

跨 socket 测量首次缺失观测后，若仍有三个未联系的主 socket/目的端组合，可在同一份 1200 ms 总预算内转为主 socket 尾段测量，最多切换一次。原始发送账本全部保留，请求总数不增加；未完成的交叉测量仍不能授予固定锚所需的共享分配器证据。测量通道的排队不消耗 fresh generation：未进入测量即超时、取消或身份失效时，仅返还原恢复 epoch 中对应的保留资格；开始测量后失败不返还。

测量的 socket 可写等待、网络代际准入和响应等待共享同一个请求截止，同时受原 1200 ms 总截止限制；等待发送时不持有网络代际锁，最终非阻塞发送才进入该锁。取消、Direct 提升和网络变化在等待期间定期复查，并在发送前再次核对。同一 UDP transport 内的实时 STUN 响应等待项最多 256 个，响应完成或所属请求被取消、丢弃时按精确所有者释放，不依赖迟到响应清理；容量不足不挤掉已有请求。

双方协商一个包含候选顺序、策略、注册身份、phase 和截止时间的计划。按证据选择固定锚、多端口预测或生日探测；固定锚只在双方测量均支持时使用 2、4 或 8 个 socket，首波覆盖全部选定 socket，后续波次保持原 socket 与目标配对。单 socket 预测窗口最多 32 个候选。完整同方向尾段可生成有界的连续后继假设，覆盖信令等待期间其他设备可能消耗的端口；主 socket 的完整尾段仍规律时保留低成本的单 socket 尝试，观察到跳号时使用完整生日窗口，最多发布 96 个候选。后继假设不推断未观测到的回绕、分配作用域或固定锚；缺少可用尾段时，生日候选继续使用与端口域互素的步长避免短周期重复。候选数量、唯一 socket/目标组合和重复发送分别计数。

双方均为完整的固定步长窗口时，initiator 保持收到的候选顺序，responder 在双方窗口长度的较小值内按共同 phase 重排，超出共同前缀的远端候选保持原序。此顺序也适用于双方完整的生日后继窗口；稀疏、混合或随机候选不参与重排。候选数量、协商摘要和协议不变；每个 phase 的条件覆盖只适用于共同前缀，不代表一次尝试能覆盖所有分配偏移。`hh2` 使用协商计划中的共同 phase；兼容流程沿用 fresh generation 的 phase。此顺序不适用于稀疏窗口或随机映射，也不保证发送期间发生其他端口分配时仍可连通。

完整窗口的顺序检查允许已观测端口域产生的循环固定步长，不把所有回绕都限定为 65536。检查只验证所发布候选在同一循环中的连续顺序，不生成新的 NAT 端口域证据；同号不等步长、多个不一致步长、跨越推导环宽的端口跨度和半环歧义仍被拒绝。

测得的控制 RTT 不足 1 ms 时，信令将其编码为 1 ms，避免与“没有时钟样本”的零值混淆；真实不确定度与缺失样本的保守处理保持独立。

READY 确认计划，SYNC/SYNC_ACK 将最终首发时间绑定到该计划；首发可在原有截止前提前，不能延长测量预测时距。READY 重传后不将无法归属的响应时延作为 RTT 样本；预测和固定锚同时预留首波的发送节奏余量。首发时间还必须在原会话有效期内留下完整的 3 秒发现和 2 秒确认窗口，窗口不足则停止该计划，不延长会话。收到对端确认与本端 HTTP 请求完成是不同证据，HTTP 响应延迟不会撤销已经接收的有效确认。最终确认的上传失败可在预扣的原 HTTP 配额内重试，最多 3 次，复用同一报文且不超过原首发截止。全局候选队列和每 peer 队列拥塞时，保留该命令并在原截止内等待容量，不重复扣额或构造新报文；等待继续检查取消和注册身份。

`hh2` 初始 OFFER 和 ANSWER 在原截止、恢复身份和 HTTP 配额内最多发送两次；重试复用同一份已准备报文，短窗口可只发送一次。接收方在候选变更之前识别同 token、同计划的重复信令，避免重试触发新的候选 epoch；同 token 的冲突内容被拒绝并保留已有会话。首次 ANSWER 的计划确认与后续执行认领使用同一份已提交记录。

READY、READY_ACK 和 SYNC 同样绑定原注册身份与阶段截止，并在两层候选队列内保留同一条预付命令。每次 HTTP 的 400 ms 窗口从命令出队、完成身份检查后开始；排队不启动新的 HTTP 尝试计时。下一次重试继续由原协商 owner 控制，阶段推进或取消会终止等待，总配额不增加。

接收 READY/SYNC 屏障时，本地锁竞争在原计划首发截止内有界等待，并继续驱动已有工作通道；取消、关闭或过期后终止该信令。不会因一次 50 ms 本地等待超时而转入服务端的长租约重投递。REST 投递确认复用原 signal ID、delivery token 和注册身份，最多重试 3 次，不重新执行应用逻辑。HH2 确认的单次 HTTP 上限为 400 ms，总等待不超过剩余信令时间和 1250 ms 的较小值；应用已终止或时间缺失时只做一次 400 ms 内的清理确认。每次发送、响应和重试等待均检查注册身份，身份变化立即停止。同批信令仍按顺序完成应用，投递确认通过有界队列串行发送；前一条确认响应丢失不会阻塞已租用的后续屏障应用，未完成应用的信令不会被确认。

单个 Control 客户端的候选发送最多保留 32 条 peer 通道，每条通道串行执行一个 HTTP 请求，因此候选 HTTP 并发同样不超过 32。通道空闲 1 秒后关闭入口并处理已接纳的队列，任务结束后按精确任务身份回收；旧通道尚未完成时不并行建立同 peer 的替代通道。HH 命令遇到通道容量不足时复用唯一待派发位置，在原截止内等待；普通新 peer 候选报告明确的容量失败。握手应答、握手发起和控制命令继续使用独立通道，运行任务分别最多 4、4、2 个；未运行的命令保留在有界 channel 中，不创建额外的许可等待任务。取消和关闭会释放所属任务。

注册身份被撤回后，原投递通道停止确认，并最多等待 2 秒取得同服务、同设备的当前授权，再通过当前网络的 HTTP 连接池向 `POST /api/v1/signals/release` 发起一次最多 1 秒的租约释放请求。服务端逐条匹配接收设备、signal ID 和旧 delivery token，只清除租约，不删除信令；下一次投递生成新 token，仍按原 peer 顺序处理。迟到的旧确认和释放不能影响新租约，未完成应用继续由原应用跟踪器合并。请求最多包含 500 条投递；旧服务端返回 404/405、恢复超时或请求失败时继续依靠原租约到期重投。

周期候选采集在开始时记录候选快照版本、网络代际和 UDP 发布身份，完成 STUN 与网关发现后在提交处再次核对；较慢的旧采集不能覆盖期间已更新的候选、NAT profile 或 socket pool 策略。仅端口变化的延迟发布仍使用固定 500 ms 窗口；最新候选恢复为已发布集合时，撤销尚未发布的旧变化。

候选向在线 peer 扇出前会在等待并发许可后再次核对网络代际、peer session、Direct 健康状态和最新候选快照；同一身份围栏还会在控制通道的 per-peer 队列及认证等待后、实际 HTTP 请求前重新核对。身份替换、已成功直连或快照被新集合覆盖时不再启动旧 OFFER 的本地发送；请求已在途时远端是否接纳仍可能不确定，后续旧代际的本地打洞不会继续启动。

每个恢复 epoch 最多提供 4 次 Hard↔Hard 新测量，耗尽后继续使用普通恢复流程。重试由已有调度器串行触发，每次重新测量、协商和核对身份；每周期总计最多 32 次候选 HTTP 发布，普通恢复与协调打洞共享此额度，UDP 总额度仍为 4000。候选变化、重试和测量失败不补充额度。协调打洞使用高于普通单向预测的本地会话优先级，同时保留原有首发保护窗口和身份替换规则。

上一轮协调打洞已取消但仍持有清理许可时，新请求最多等待 500 ms，让精确旧 owner 的最后一个引用释放，再重试一次认领。等待前退还测量预留，等待后重新核对会话、网络、计划、恢复身份和时间窗口；清理超时或仍在运行的同级 owner 不会被强制接替。

按协调 token 清理套接字时，先从权威注册表撤下精确条目，再释放这些条目的待确认探测，避免无效 ACK 等待为每个落选 socket 累积两秒宽限。已提交的 Direct 或明确保留的 socket 不参与此清理；已经取得的发送租约仍按原有界流程排空。

Hard↔Hard 的全部生日探测 worker 与重复波次共享 5 ms 发送节奏，继续接受原有每 peer/目标 IP 每秒 224 次及全局、持久和恢复 epoch 预算检查。`hh2` 在原总预算内为认证后的重复探测和提名预留额度，探索扫描不能耗尽这部分额度；responder 对已选精确候选对的确认可使用末尾保留额度，普通候选探测不可使用。其他流量仍可能竞争全局预算。短期限流只在原 3 秒 sweep 窗口内重试，等待后重新验证会话和网络身份；持久限流不通过等待绕过。兼容副本单独计入物理 datagram 成本。恢复身份失效、总额度耗尽或只剩确认保留额度时，同一扫描的 socket 与后续波次停止探索；身份或恢复额度拒绝不会扣除进程级扫描额度。预算锁竞争按有界暂缓处理，不作为 NAT 预测失败。

测量 socket 在发布和 rendezvous 期间保持隔离。固定锚的本地测量租约保留到首波全部 socket 发出，成功、取消和失败均释放租约；它不能阻止 NAT 后其他设备分配端口。认证 Probe 命中只生成待确认的精确候选对。重复探测、提名 ACK 和最终加密验证均绑定本地 socket、远端 endpoint、session token 和当前生命周期。Direct 提交及其业务路径快照发布完成后才清理同 token 的落选 socket、pending probe 和 reader；迟到旧协议报文不能激活已退休的 `hh2` socket。

候选对确认分别处理短期限流、明确未发送、发送结果不确定和身份失效。短期限流等待原窗口恢复，明确的本地未发送允许有限补偿；两者都受原发现或确认截止约束。结果不确定保留已计入的尝试，身份失效立即停止。补偿不返还进程级或恢复 epoch 的发包额度。

已选候选对的加密验证观察在原确认截止前有界重试，入队、合并或队列背压不消耗实际 Request 次数。计数只在 UDP 成功提交 Request 时增加，每个候选对会话累计最多 48 次、单个验证 worker 最多 3 次；ACK 不占 Request 次数。验证租约绑定原 token、精确候选对、网络和 peer session，排队或重新获得 worker 不刷新截止时间、不重置累计计数。

验证 owner 结束时，先在网络代际保护下清理同 owner 的路径验证状态，再移除会话和 ACK 等待项。清理中的异步等待若被取消，原 owner 身份仍可用于继续清理；旧 owner 的迟到清理不能撤销新 owner。

固定锚的前缀覆盖假设不包含首波各 socket 发包之间的外来分配；这类交错消费仍可能使所有 socket 错过锚点。生日探测的后续波次复发原 socket/目标组合，用于弥补时序和丢包，不增加独立映射样本数。

策略学习只接受当前网络、模型与会话的有效结果。成功反馈来自最终 Direct 提交；失败反馈只由已收到最终对端确认的 initiator 记录，并要求计划完整执行、没有预算或发送错误且未收到认证响应。取消、不完整执行和信令结果不确定不作为策略失败。学习只调整有限策略顺序，不扩大预算，也不把样本一致性当作实际成功率。高熵随机映射叠加严格过滤时仍可能无法 Direct，Relay 保留为回退路径。

策略建议最多保存 64 个 peer，闲置有效期为默认恢复周期的三倍（90 分钟），分数每两个恢复周期（60 分钟）向零衰减；读取建议不会续期。相同网络、peer session 和双方 profile generation 的有效经验可影响下一轮，同分策略在实际结果后有界轮换。身份变化会使旧建议失效；建议不授予新的测量许可或探测额度。

Hard↔Hard 日志区分模型生成数量、归一化入口数量、进入信令数量和实际探测统计。`pre_normalization_reduced_count` 表示调用方在归一化之前已裁掉的候选数量；例如模型生成 96 个而当前策略只接受 32 个，不能报告为已经实际覆盖 96 个。

已解密的 Direct 验证请求和 ACK 遇到本端发送锁竞争时，最多等待 100 ms，并在每次重试时核对原 transport session instance；等待不持有发送锁或会话表锁。锁竞争超时与真实会话替换分别报告，真实替换仍拒绝旧帧，后续 peer lifecycle、网络 generation 和验证 owner 检查继续生效。ACK 获得当前实例保护后，将保护保持到 Direct 状态及业务路径快照提交完成，这段提交另有 100 ms 上限；超时不回滚已经完成的提交。请求处理在加密回复之前释放实例保护，避免重复获取发送锁。
