# 安全模型

P2WLAN 从架构设计层面遵循最小特权原则、端到端零知识数据加密以及严格的隐私保护机制。本篇文档介绍系统的安全边界、凭据体系与隐私设计。

---

## 1. 身份与凭据分级体系

P2WLAN 将不同层级的操作凭据严格隔离，防止凭据滥用或单点越权：

| 凭据类型 | 用途范围 | 有效期 | 存储与保护 |
| --- | --- | --- | --- |
| **Control 登录 JWT** | 客户端向控制面进行用户身份认证 | 较长 | 客户端安全存储，仅与 Control 通信 |
| **Relay 访问票据 (Ticket)** | 客户端接入中继服务器的认证凭据 | 短期（分钟级） | 由 Control 动态签发，绑定目标 Region 与设备 |
| **数据面端到端密钥** | 节点间点对点通信会话密钥 | 会话级 | 节点间协商（Noise 框架），私钥永不离机 |
| **Web 管理员 Token** | 访问 `/admin` 运维控制台的只读凭据 | 静态随机强密钥 | 独立保存在服务端配置文件中，不与用户身份混用 |
| **撤权流同步 Token** | Control 与 Relay 之间同步黑名单 | 长期静态密钥 | 内部服务间鉴权，隔离于外网访问 |

---

## 2. 数据面零知识转发

- **端到端加密通道**：所有进出虚拟网卡（TUN）的用户业务报文，均在客户端本地进行加密封装后再行发送。
- **中继无感知转发**：当走 Relay 中继时，Relay 节点仅根据报文头部的加密票据与目标节点 ID 转发密文数据包。中继服务器**完全无法解密、窥探或篡改**任何用户的业务载荷明文。
- **重放攻击防护**：数据包包含严格单调递增的计数器序列与防重放滑动窗口，杜绝网络嗅探重放风险。

---

## 3. 路径遥测与隐私保护

客户端 Daemon 会向 Control 上报当前链路状态，以支撑运维大盘与连接健康监测。遥测设计严格遵循**最小泄露原则**：

- **零 IP / 零端口泄露**：上报的遥测数据仅包含抽象状态（如 `direct` / `relay`）、端到端 RTT 采样与迁移状态码，**绝不记录或持久化任何设备的真实物理公网/局域网 IP、端口或打洞候选地址**；
- **零载荷接触**：遥测仅涉及网络连通性元数据，不包含任何报文数据或密钥；
- **时序与代际防护**：通过分层代际编号（Fencing Generations），服务端能自动过滤过时或网络切换期间的陈旧上报，保证数据反映当下真实状态。

---

## 4. 本地守护进程与权限管理

- **本地诊断接口隔离**：桌面 Daemon 暴露的本地诊断接口（默认 39277 端口）仅监听于 `127.0.0.1`，并采用每次启动随机生成的 Bearer Token 进行访问保护，防止同机其他非特权程序探听网络状态；
- **最小权限运行**：日常 CLI 命令与图形界面均运行在普通用户权限下。仅在创建虚拟网卡（TUN）与修改系统路由表时，系统会按需申请系统提权（如 Windows UAC、macOS 授权弹窗）；
- **配置与日志保护**：生成的敏感配置文件与运行时套接字均采用严格的文件系统权限（Unix `0600` / `0700`），防止同机未授权用户读取。
