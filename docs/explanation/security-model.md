# 安全模型

## 身份与凭据

设备控制面身份、数据面会话密钥、Relay ticket、JWT、管理控制台令牌、Relay 票据签名 key、撤权 feed token 和 TLS 私钥承担不同职责，不能互相替代。管理控制台令牌只授权同一 Control 实例的只读管理 API，不授予设备身份、房间成员身份或 Relay 数据连接权限。ticket 必须绑定 audience、region、设备/网络身份和短期过期时间；Relay 在撤权 feed 未就绪或过期时拒绝新的认证连接。

账号 JWT 使用持久配置中的签名密钥，有效期为 7 天；设备凭据只在服务端保存摘要及有效期、撤销状态。进程重启不会清除这些身份材料，设备重新注册也不会自行撤销已有凭据。认证存储不可用时拒绝执行请求并返回可重试的 503，不把查询失败解释为账号退出、凭据撤销或注册代际冲突；真实的过期、撤权和旧注册请求仍然拒绝。更新服务端不会延长凭据的原有有效期。

默认配置接受 Control 成员列表中的身份映射。启用严格对端验证后，客户端只接受当前网络的本地信任名单，要求设备 ID、完整 X25519 公钥和虚拟 IPv4 地址全部匹配。公钥应通过独立可信渠道核对。握手继续验证对端持有相应私钥，Control 仍负责成员授权、信令与服务可用性。房间密码只用于 Control 的加入授权。

既有配置默认以十六进制保存设备私钥。显式迁移后，配置只持有封装的 X25519 和 Ed25519 私钥。Unix 使用外部提供的独立随机密钥，Windows 可使用绑定当前用户的 DPAPI。解锁失败会阻止加载该配置。配置目录之外的解锁材料、已有明文备份、其他凭据以及运行中的端点进程仍需保护。

Control 登录与注册的来源限流表各最多保留 4096 个来源，满时新增来源共用 overflow 预算，活跃来源不会因地址轮换被驱逐。设备 REST 请求读取有界 JSON、写回响应及空闲信令等待时不持注册锁；恢复消费前重新核验凭据与注册代际。设备锁只在持有或等待时保留，总使用者上限为 4096，取得锁最多等待 5 秒，调用方取消或超时即释放等待位置；达到容量或等待上限时返回不同错误码的可重试 503，不强制释放已经取得的锁。

daemon 的 Control HTTP 客户端不自动跟随重定向，避免将请求体或认证信息转交给重定向目标。部署者需要填写最终的可信 HTTPS 地址，并让反向代理直接处理 API 与 WebSocket 路径；HTTP 地址本身仍是明文传输，不能用于公网凭据交换。

## 本地诊断认证

桌面 daemon 的本地诊断密钥按进程生成，重启时更换，没有闲置到期机制。客户端每次请求读取当前发现文件；`/health` 可公开探活，`/status` 等私有接口仍要求 Bearer 认证。本地 401 不能解释为 Control 登录到期，也不能证明已有 Direct 或 Relay 数据面已停止。

诊断发现目录由独占文件锁保护，同一目录不能同时供多个 daemon 发布密钥。不同配置或端口的实例必须使用各自的运行目录。密钥文件被清理后，持有发现目录锁的进程可重新发布同一密钥；Unix 发布保持 `0600`，提权进程保留启动时确定的目录所有者，Windows 保留交互用户的受限 ACL。退出清理只删除仍匹配本进程密钥的文件，不删除锁文件或继任实例的凭据。

Unix 发现目录的发布、修复和清理绑定目录与锁文件句柄。重建最后一级目录时保留原属主及 `0700`，不递归重建缺失的祖先，也不接管其他用户或重定向后的目录。桌面启动的遗留权限恢复只接受 sudo/pkexec 声明的实际调用 UID，并以账户数据库中的主目录限定默认应用路径；固定文件逐个验证，活动锁冲突时拒绝恢复。提权 daemon 原子保存配置时继承已固定配置目录的属主，新文件及替换文件均为 `0600`。

## 数据面

业务数据在端点之间使用加密会话。Relay 看到节点标识、时间、连接频率和包大小等元数据，但不应看到业务明文。Direct 只有在当前 generation 下完成加密确认后才能成为有效路径；旧候选、旧 peer session 和旧授权成员不能提升路径。

数据面使用项目自包含的 WireGuard-like Noise 实现，不声明与官方 WireGuard 互操作或具有其独立审计结论。X25519 拒绝产生全零共享秘密的对端输入。Noise 对称状态、握手 PSK 和传输密钥持有者在正常释放时自动清零；临时副本、配置字符串、交换区与崩溃转储不由这项保证覆盖。

Relay 明文传输默认关闭，只有本地显式设置 `relay.allow_insecure_plaintext=true` 才可用于隔离开发环境。HTTP Control 地址、远端 catalog 或明文 Relay endpoint 都不能自动放宽该设置。业务载荷的端到端加密不能保护明文 Relay 连接中暴露的认证票据与路由元数据。

Relay 认证限流最多保留 4096 个来源桶，过期后回收；容量耗尽时新增来源共用 overflow 预算，不驱逐活跃来源以重置其限流。转发帧携带精确源会话身份，在延迟结束与目标 writer 开始真实写入前复核源、目标当前身份；撤权或连接替换后的旧排队帧被拒绝。已经开始真实网络写入的帧可能完成，网络 I/O 不持有 hub 锁。

Relay ticket 在 `exp` 到达时即失效，clock skew 不延长到期时间；已经到期的替代连接不能驱逐健康的当前连接。认证、实际发布、延迟后的转发与 writer 开始写入都检查该到期时间，不依赖到期定时器已经获调度。

## 路径可观测性与隐私边界

Direct 对端可看到实际连接地址，网络观察者可看到外层端点、包长、频率和时序。Relay TLS 保护连接内的协议字段，Relay 本身仍能观察转发关系。

支持该能力的 Control 和双方客户端可使用 PNCH v3。源和目标由探测会话密钥派生为临时标签，报文继续验证 HMAC 和会话身份。同一会话内的探测仍可关联，旧版本兼容的 PNCH v2 仍携带稳定节点标识。能力协商依赖 Control 提供的注册信息。客户端发送 STUN Binding Request 时省略可选的 SOFTWARE 属性。

客户端 daemon 到 Control 的活动路径遥测严格遵循最小泄露与代际围栏原则：
- 遥测仅传输抽象路径类型（direct、relay、connecting、probing、fallback_relay、failed、none）、往返 RTT、握手代际围栏标识与迁移原因代码。
- 绝不持久化或传输任何 IP 地址、端口、候选 endpoint、WireGuard 密钥、对称会话密钥或报文载荷。
- Control 校验上报端设备的会话凭据（WebSocket 认证或设备 token）、设备所属权与网络归属，并通过五级代际围栏（`registration_seq` > `network_generation` > `peer_session_generation` > `remote_candidate_epoch` > `observation_revision`）防御陈旧、越权或重放的路径上报。
- 只有持有 `CONTROL_ADMIN_TOKEN` 的管理员可通过只读 Admin Connections API 检索路径观测记录、受限历史迁移和小时级趋势聚合，普通节点不能任意拉取其他节点的路径观测。趋势表只保存 network ID、小时 bucket、计数与 RTT histogram，不长期保存 peer/device ID、IP、endpoint、密钥或业务载荷。

## 运维边界

Control 明文监听、Relay metrics、数据库、配置和密钥文件默认只在受保护的本机或容器网络中可见。公网只发布可信 HTTPS Control 和 Relay TLS。管理控制台如果启用，也只通过可信 HTTPS Control origin 访问；其令牌不写入公开日志、URL 或文档。日志、支持包和备份按敏感数据处理，不能把私钥、token、ticket 或业务明文写入公开产物。

项目尚未完成独立安全审计，不声明安全认证。测试覆盖、CI 门禁和发布 manifest 不能替代外部审计或部署者自己的风险评估。
